# HH AI Agent

Агент автоматически ищет вакансии на HH.ru, оценивает их через LLM, генерирует сопроводительные письма и присылает подходящие в Telegram.

## Быстрый старт

Запусти мастер настройки — он проведёт тебя через все шаги:

```bash
python setup_wizard.py
```

Wizard спросит:
1. Токен Telegram-бота и твой User ID
2. Ключ OpenCode Go и модель (`deepseek-v4.1-flash`)
3. Данные твоего профиля для анализа вакансий
4. Режим работы (`dry_run`, `approval` или `auto`)

После этого создаст `.env` и `profile.yaml`, проверит конфигурацию и покажет что делать дальше.

**Изменить настройки позже:**

```bash
python setup_wizard.py --edit
```

## Режимы работы

| Режим | Описание |
|---|---|
| `dry_run` | Ищет и анализирует вакансии, присылает превью в Telegram — **без реальных откликов** |
| `approval` | Присылает вакансию в Telegram с кнопкой «Откликнуться» для ручного подтверждения |
| `auto` (автоподача) | Автоматически откликается на все подходящие вакансии без AI/LLM, заполняет анкеты по легенде и решает капчу. Вакансии с AI/LLM и формы с файлами приходят в Telegram для ручного отклика |

Начинай с `dry_run`. Переходи на `approval` или `auto` после того как убедишься что всё работает.

Карточка вакансии показывает краткое объяснение совпадения, рейтинг компании с HH и сворачиваемое сопроводительное письмо. Если rich messages недоступны, бот отправляет обычную HTML-карточку.

### Автоподача

Для включения режима нужны настройки:

```dotenv
APP_MODE=auto
ENABLE_REAL_APPLY=true
AUTO_APPLY_ENABLED=true
```

В режиме `auto` бот откликается на все вакансии, которые LLM признал подходящими, если в них нет AI/LLM. Вакансии с AI/LLM всегда остаются в Telegram для ручного отклика с индивидуальным письмом. Анкеты работодателя заполняются из легенды (`LEGEND_PATH`, по умолчанию `legend/legend_full.json`) короткими ответами на 1–2 предложения. Письма и ответы анкет проходят анти-машинную постобработку: без тире, скобок, слэшей, канцелярита и штампов. Капча сначала распознаётся через LLM с поддержкой изображений, а при неудаче приходит в Telegram. Если в форме требуется загрузить файл или выполнить тестовое задание, бот не отправляет отклик и присылает вакансию в Telegram.

Размер пачки, интервалы и рабочее окно задаются через `AUTO_APPLY_*` в `.env`. Каждый успешный автоотклик приходит в Telegram с названием компании и прямой ссылкой на вакансию. Размер пачки рассчитывается от остатка дневной квоты и числа оставшихся пачек в рабочем окне: по умолчанию 12–15 откликов раз в час с 08:00 до 22:00 МСК, до 120 в день. Агент продолжает поиск до достижения размера пачки. Если состояние отправки нельзя подтвердить, circuit breaker приостанавливает следующие отклики.

### Свежесть выдачи

По умолчанию бот смотрит только свежие вакансии и сортирует их по дате публикации:

```dotenv
HH_ORDER_BY=publication_time
HH_SEARCH_PERIOD=1
```

- `HH_ORDER_BY` — `publication_time` (свежие сверху) или `relevance` (по соответствию)
- `HH_SEARCH_PERIOD` — `0` всё время, `1` сутки, `3` три дня, `7` неделя

Так новые вакансии не теряются среди старых, а повторные циклы не перебирают одну и ту же выдачу.

### Отсев нерелевантных ролей

До LLM вакансия проверяется по названию. В `profile.yaml` есть `excluded_positions`:
если название содержит запрещённую роль, вакансия сразу уходит в `rejected_by_filter`.

Базовый список отсекает:

- стажёров и junior;
- 1С, HR, SMM, продажи, маркетинг;
- `Product Manager`, `Product Builder`, `Product Engineer`, продактов, `Product Owner`, владельцев продукта;
- `Project Manager`, `Process manager`, руководителей проектов;
- `Data Engineer`, `Data Analyst`, аналитиков данных;
- программистов и разработчиков, включая `1С` и ИИ-разработку.

Архитекторы при этом не отсекаются: `Корпоративный архитектор` и `ИТ-Архитектор` проходят дальше.

## LLM: OpenCode Go

Бот работает через **OpenCode Go** — OpenAI-совместимый шлюз. Отдельный прокси для LLM не нужен:
запросы идут напрямую на `https://opencode.ai/inference/go/openai/v1`.

### Настройки

```dotenv
LLM_PROVIDER=openai_compatible
LLM_MODEL="deepseek-v4.1-flash"
LLM_TIMEOUT_SECONDS=120
LLM_MAX_RETRIES=2
LLM_TEMPERATURE=0
LLM_MAX_OUTPUT_TOKENS=4000
LLM_MAX_REQUESTS_PER_DAY=2000

OPENAI_COMPATIBLE_BASE_URL="https://opencode.ai/inference/go/openai/v1"
OPENAI_COMPATIBLE_API_KEY="ваш-ключ-opencode-go"
OPENAI_COMPATIBLE_JSON_MODE=true
OPENAI_COMPATIBLE_REASONING_EFFORT=low

CAPTCHA_MODEL="deepseek-v4.1-flash"
```

### Модели

- `LLM_MODEL` — основная модель для анализа вакансий, письма и анкеты. Сейчас `deepseek-v4.1-flash`.
- `CAPTCHA_MODEL` — vision-модель для капчи. Сейчас та же `deepseek-v4.1-flash`, потому что она умеет смотреть изображения.
- `OPENAI_COMPATIBLE_REASONING_EFFORT=low` — не тратить лишние reasoning-токены на короткие ответы.

### Особенности OpenCode Go

- OpenCode Go требует заголовок `x-opencode-session`; бот добавляет случайный UUID на каждый запрос автоматически.
- `CAPTCHA_SWITCH_TO_ENGLISH=true` — если HH показывает кнопку смены языка, бот переключает капчу на английскую: латиницу модель читает лучше.
- `LLM_MAX_OUTPUT_TOKENS=4000` обязателен: на 1500 reasoning-модель обрезает JSON и вакансия падает с `finish=length`.
- `LLM_TIMEOUT_SECONDS=120` — запас на медленные ответы. Штатно модель отвечает за 2–5 секунд.
- Для капчи используется отдельный вызов с `max_output_tokens=4000`: DeepSeek тратит reasoning-токены до ответа, на 200 приходит `finish=length` и пустой ответ.

> Текст вакансии и данные профиля уходят в OpenCode Go. Ключ хранится только в `.env`, в git не попадает.

## Безопасность

- Реальный отклик требует `APP_MODE=approval` + `ENABLE_REAL_APPLY=true` и либо нажатия кнопки твоим Telegram ID, либо отдельно включённой автоподачи с достаточным confidence
- Автоподача выключена по умолчанию и ограничивается размером пачки, рабочим окном и дневным лимитом
- Ссылка на портфолио может быть объявлена обязательной; без неё письмо не будет отправлено
- После начала отправки неопределённый результат резервирует дневной слот и останавливает автоматическую серию, чтобы не создавать дубли
- `.env`, `profile.yaml`, `legend/` и `.browser-profile/` исключены из Git
- Токены, cookies и полный `.env` не записываются в логи

## Типичные ошибки

| Ошибка | Решение |
|---|---|
| `Configuration error` | Заполни все обязательные поля через `python setup_wizard.py --edit` |
| `CloakBrowser failed to start` | Проверь `python -m cloakbrowser info`, при необходимости смени на `BROWSER_BACKEND=playwright` |
| `HH.ru login is required` | Запусти с `BROWSER_HEADLESS=false` и войди вручную |
| `LLM check failed` | Проверь endpoint, ключ и дневную квоту через `python main.py --check-llm` |
| `Invalid model response` | Проверь модель и `LLM_MAX_OUTPUT_TOKENS` — вакансия безопасно пропускается |

## Ограничения

- Автоматизация может нарушать правила HH.ru — ответственность за аккаунт несёт пользователь
- CloakBrowser не гарантирует отсутствие детектирования или CAPTCHA
- Нет proxy, GeoIP-ротации и внешних CAPTCHA-сервисов
- Рассчитано на одного владельца и одну SQLite-базу
- В ручном режиме письмо можно проверить и отредактировать в Telegram; автоподача отправляет его без предварительного просмотра
